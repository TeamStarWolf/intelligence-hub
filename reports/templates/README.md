# Report edition format

Use the established weekly structure with an immutable edition ID: executive summary, selected notable developments, KEV additions, campaigns and actors, supply-chain/AI where supported, watchlist, limitations and primary-first references. Never force ten stories or fill a section with guessed facts.

Every bundle contains README.md, data.json and charts/ generated from that same edition's actual data. Keep its cadence, intended nominal slot, actual compilation timestamp, zoned half-open period, input version/hash/capture clocks, inclusion-clock recipe, source outcomes, row/count denominators and limitations. Preserve missing values and later retrospective context rather than substituting zero or historical certainty.

Citations and source assertions require attributable public evidence. Products, affected versions, fixed releases, interim mitigations, CWE/CAPEC taxonomy and actors/campaigns retain their individual scope, confidence, version and source dates. Raw HTML, private proofs, source-location crosswalks, account data and machine paths do not enter these files. Existing legacy reports remain unchanged.

Follow [the reporting method](../REPORTING.md). A calendar close establishes a window, not complete evidence. Corrections and closing editions use new IDs; compiled report/data/chart bytes stay bound to the same frozen inputs. Show the next nominal opportunity and the last actual outcome without promising punctual delivery.
